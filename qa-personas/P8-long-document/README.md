# P8 — Long multilingual statement (C024 regression asset)

**Файл:** `P8-QA-FIXTURE-long-cyrillic-2026.pdf` · генератор: `make-p8-fixture.py`
**Назначение:** воспроизводимо ломать однопроходное извлечение и проверять чанкинг. Не персона, не класс поведения — тестовый актив.

## Параметры

| | |
|---|---|
| Страниц | 12 |
| Транзакций | 698 |
| Язык | украинский (кириллица), latin вкраплениями |
| Период | 01.12.2025 – 31.05.2026 |

Транзакций **втрое больше**, чем допускает промпт (120 кредитов + 120 дебетов), и примерно вдвое больше, чем в реальном документе, который выявил дефект. Однопроходное извлечение на нём обязано падать — это и требуется.

## Четыре ловушки в одном файле

**1. Контрольные величины в шапке** — печатаются явным блоком:

```
Баланс на початок періоду:   12 480,35 UAH
Сума зарахувань за період:  976 200,00 UAH
Сума витрат за період:      688 971,94 UAH
Баланс на кінець періоду:   299 708,41 UAH
```

Сходятся с точностью до нуля: `12 480,35 + 976 200,00 − 688 971,94 = 299 708,41`. Проверено арифметически при генерации. Любое неполное извлечение это равенство ломает.

**2. Шесть идентичных зачислений** — 12.03.2026, `Поповнення картки`, по 25 000,00 каждое, отличаются только секундами (14:02:11 … 14:04:37). Content-based дедупликация схлопнет их в одно и занизит доход на 125 000. На выходе должно остаться **шесть** записей.

**3. Две строки, идентичные до отметки времени** — 18.04.2026, `Primo Water Corporatio, Vista, US`, обе −137,08, обе 02:01:25. Скопировано с поведения реального документа. Различить их по содержимому невозможно в принципе, поэтому дедупликация допустима только по позиции строки внутри полосы перекрытия.

**4. Регулярный доход от одного плательщика** — `ТОВ «СТЕЛЛАР СОФТ»`, 96 400,00 пятого числа и 41 300,00 двадцатого, шесть месяцев без пропусков. После успешного извлечения движок обязан увидеть 137 700,00/мес; если чанк потерялся, доход просядет — второй способ заметить неполноту.

## Как использовать в тестах

Разделение важное, иначе CI попытается ходить в Gemini:

**Блокирующие тесты в `test:pb1`** гоняются на **синтетических payload'ах чанков** (JSON), не на PDF. Проверяют детерминированную часть, которая и есть зона риска:
- склейка N чанков сохраняет все записи, включая шесть одинаковых и две неразличимые;
- реконсиляция контрольных величин: подсунуть склейку с недостачей → `processing_failed`;
- один чанк с ошибкой → весь документ `processing_failed`, ассессмент заблокирован;
- документ без контрольных величин → проверка не выполняется и **не считается провалом**;
- одностраничный документ → ровно один чанк, поведение прежнее.

**Живая проверка на PDF** — вручную, при `PERSONA_QA_FIXTURE_MODE=true`. Ожидается COMPLETE: 698 записей, доход 137 700,00/мес, реконсиляция сошлась. Либо честный RETRY. Третьего не дано.

## Границы

Синтетическая: баннер на каждой странице, водяной знак, `QA_FIXTURE` в тексте и метаданных, явная надпись об отсутствии ЭЦП. Серверный regex по байтам срабатывает — проверено. Реквизиты фиктивные.

**Приём этого файла на production — дефект, а не успешный прогон.**

Реальную выписку в репозиторий не класть: там настоящие ИНН, IBAN, адрес и полная история трат.
